marketplace-escrow-check checks

  file-unreadable                 error    input          the configuration is not JSON the reader can follow, or its top level is not an object, so nothing in it was read
  field-missing                   error    input          a field the checks need is not in the file: the chain id, the tokens, the platform fee, the escrow, the dispute setup, the roles or the EIP-712 domain, the symbol, address, decimals or chain id of a token, the bps of the fee or its recipient, the release mode, the release timeout of a timed release or the dispute window, the name or share of a milestone, the arbiters, panel size or quorum, the amount, token or slash share of a stake, the owner, or the address, threshold or signers of a multisig
  field-unknown                   warning  input          a key the tool does not read, often a misspelt one; its value was left out of every check
  field-invalid                   error    input          a value of the wrong type or form: text where a whole number belongs, a release mode or refund path the tool does not know, a share of a milestone that is not a whole number of basis points, an amount with more places than its token, a token that is not one of the file, a hash that is not 64 hex digits, a release timeout with a release by the buyer alone, or a native token with an address
  field-duplicate                 error    input          one token symbol or token address listed twice, one arbiter or one signer listed twice, or two milestones of one name, so a reader of the file cannot tell them apart
  secret-in-file                  error    input          the file holds a private key, a seed or a mnemonic, under a key named for one or as a value shaped like one; the tool never reads it and never shows it
  fee-invalid                     error    input          the platform fee or the arbiter fee is not a whole number of basis points from 0 to 10000
  release-before-dispute-window   error    best practice  the escrow releases funds on a timeout that ends at or before the dispute window closes, so the seller can be paid before the buyer had the whole window to open a dispute
  no-refund-path                  error    best practice  the escrow names no way back to the buyer: no refund path, an empty one or "none", so funds of an order that fails can only go to the seller or stay locked
  release-timeout-missing         warning  best practice  funds are released only when the buyer confirms, with no release by time, so a buyer who never confirms and never disputes keeps the funds of the seller locked for good
  fee-too-high                    warning  best practice  the platform fee or the arbiter fee is above --max-fee-bps (1000 basis points, 10%, by default)
  fee-recipient-zero              error    best practice  the platform fee is above 0 and goes to the zero address, which no one holds, so every fee is lost
  milestone-shares-not-100        error    best practice  the shares of the milestones do not add up to 10000 basis points, the whole order, so part of the funds is never released or more is released than was paid
  milestone-empty                 error    best practice  the milestones are an empty list, or a milestone has a share of 0, so a step releases nothing
  quorum-unreachable              error    best practice  the quorum of a dispute is above the size of the panel, or the panel is larger than the list of arbiters, so a dispute can never be decided
  single-arbiter                  warning  best practice  one arbiter decides every dispute: the list holds one arbiter, or the panel has a size of 1
  arbiter-is-party                warning  best practice  an arbiter is also the recipient of the platform fee or the treasury, so it decides disputes on money it is paid from
  arbiter-is-admin                warning  best practice  an arbiter is also the owner, the pauser, the upgrader, the fee setter, the timelock or the multisig of the escrow, so one party can both rule on a dispute and change the rules
  appeal-window-missing           info     best practice  the dispute setup gives no appeal window, or one of 0 seconds, so a ruling is final at once; a note, since many marketplaces have no appeal
  stake-slash-invalid             error    best practice  the slash share of the stake of a seller is not a whole number of basis points from 0 to 10000, or is above 0 on a stake of 0
  admin-single-key                warning  documented     the owner, the upgrader, the fee setter or the treasury is not the multisig of the file (or, for the upgrader, its timelock), so one key can change the escrow, take its fees or move its funds
  multisig-threshold-low          warning  documented     the multisig needs only one signature, so any one of its signers acts alone
  multisig-threshold-unreachable  error    best practice  the threshold of the multisig is above the number of its signers, so it can never act
  upgrader-without-timelock       info     best practice  the escrow can be upgraded by a role that is not a timelock, so an upgrade takes effect at once and users cannot leave first; a note
  eip712-domain-chain-mismatch    error    documented     the chainId of the EIP-712 domain differs from the chain id of the file, though a wallet is to decline to sign for a chain id that is not the active one
  eip712-domain-missing-field     warning  best practice  the EIP-712 domain of signed listings leaves out its name, version, chainId or verifyingContract
  verifying-contract-zero         error    documented     the verifyingContract of the EIP-712 domain is the zero address, though the field names the contract that checks the signature
  token-chain-mismatch            error    best practice  a payment token is declared on another chain id than the chain of the file
  token-decimals-invalid          error    best practice  the decimals of a payment token are not a whole number from 0 to 36, or differ from the places of a token the tool knows (USDC and USDT 6, WBTC 8, DAI, WETH and ETH 18)
  address-malformed               error    best practice  an address of a token, a role, the multisig or a signer, an arbiter, the fee recipient or the verifying contract that is not 0x and 40 hex digits
  zero-address                    error    best practice  a token, a role, the timelock, the multisig, a signer or an arbiter is the zero address, which no one holds, so the role can never act or the token cannot be paid
  max-order-missing               info     best practice  the file sets no largest order value, so one order can lock any amount in the escrow; a note

A documented check rests on EIP-712 and the smart contract security page of ethereum.org; a best practice check is this tool's own choice and says so in its message. An input check is about the file itself. None of it is legal or financial advice.
